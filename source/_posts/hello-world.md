这里是「村雨的技术小站」的第一篇文章。

之前用 `hexo init` 生成的默认站点一直在桌面上躺着：标题是占位符，作者是 `John Doe`，主题是最朴素的 landscape，`url` 还写着 `http://example.com`。这次把它彻底改造成了可以直接对外访问的样子。

## 这次改了什么

| 项目 | 改造前 | 改造后 |
| --- | --- | --- |
| 站点标题 | `cunyu1903` | 村雨的技术小站 |
| 作者 | `John Doe` | cunyu1903 |
| 语言 | `en` | `zh-CN` |
| 主题 | landscape（默认） | NexT 8.29（Mist 方案） |
| 搜索 | 无 | 本地搜索（无需第三方服务） |
| 订阅 | 无 | RSS / Atom |
| 部署 | 无 | GitHub Actions → GitHub Pages |

## 为什么选 NexT

选它主要有三个原因：

1. **中文支持到位**，菜单、分页、右下角提示都会自动显示中文，不用自己翻译
2. **功能是标配的**，目录、深色模式、本地搜索、代码复制按钮、阅读进度条都开箱即用
3. **配置写在独立文件里**，主题本身装在 `node_modules` 中，升级靠 `npm update`，不会污染主题源码

## 后面写什么

不打算把它做成一个"资讯搬运站"，主要写三类东西：

- **笔记**：某个工具、某个库的用法，以后自己回查方便
- **实验**：靶场、复现、配置调试的过程记录
- **折腾**：博客本身、编辑器、自动化脚本这类

文章不会很长，但尽量写得能复现、能验证。

## 一句提醒

如果你也想搭一个，最容易踩的坑是 `url` 和 `root` 配错——它不会报错，只会让页面里的 CSS、JS 全部 404。部署到用户站（`用户名.github.io`）时 `root: /`，部署到项目站（`用户名.github.io/仓库名`）时 `root: /仓库名/`。
